# bsd_backup.sh

Скрипт резервного копирования для FreeBSD. За один запуск он:

1. делает дамп базы данных (PostgreSQL или MySQL) в `<host>-<дата>.db.gz`;
2. архивирует файлы, скажем, Confluence и системные конфиги в `<host>-<дата>.tar.gz`;
3. выгружает оба файла на NAS по `scp`;
4. удаляет локальные копии старше заданного срока.

Скрипт написан на POSIX `sh`: в базовой системе FreeBSD bash отсутствует, а `/bin/sh` есть всегда.

## Что попадает в бэкап

| Что | Откуда |
|---|---|
| База Confluence | `pg_dump` / `mysqldump` |
| Домашний каталог Confluence (вложения, индексы, `confluence.cfg.xml`) | `/var/db/confluence-home` |
| Конфиги Confluence (`server.xml` и др.) | `/usr/local/confluence/conf` |
| Конфиги пакетов | `/usr/local/etc` |
| Системные конфиги | `/etc` |

Пути, которых нет на сервере, пропускаются с записью в лог. В `BACKUP_PATHS` допускаются шаблоны (`*`) и пути с пробелами, по одному на строку.

Без дампа базы Confluence восстановить нельзя: страницы, пользователи и история хранятся в БД, а не в файлах.

## Настройка

Все параметры задаются в начале скрипта:

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `BACKUP_DIR` | Локальная директория для копий | `/var/backups/confluence` |
| `KEEP_DAYS` | Срок хранения локальных копий, дней | `30` |
| `BACKUP_PATHS` | Список директорий и файлов для архива | см. таблицу выше |
| `DB_TYPE` | `postgresql` или `mysql` | `postgresql` |
| `DB_NAME`, `DB_USER`, `DB_HOST` | Параметры подключения к БД | `confluence`, `confluence`, `localhost` |
| `SSH_KEY` | Приватный ключ для `scp` | `/root/.ssh/backup_ed25519` |
| `REMOTE_TARGET` | Куда выгружать: `user@host:/путь/` | `backup@nas.example:/confluence/` |

### Пароль базы данных

Пароль в скрипт не записывается. Его необходимо поместить в файл с правами `600` в домашней директории пользователя, от имени которого запускается скрипт:

- PostgreSQL — `~/.pgpass`:
  ```
  localhost:5432:confluence:confluence:ПАРОЛЬ
  ```
- MySQL — `~/.my.cnf`:
  ```ini
  [mysqldump]
  user=confluence
  password=ПАРОЛЬ
  ```

### Ключ для выгрузки на NAS

`scp` запускается с `BatchMode=yes`, поэтому пароль не запрашивается: при отсутствии ключа выгрузка сразу завершится ошибкой. Ключ создаётся так:

```sh
ssh-keygen -t ed25519 -N '' -f /root/.ssh/backup_ed25519
```

Публичный ключ необходимо добавить в `authorized_keys` на NAS, желательно с ограничением `restrict`. Перед первым запуском из cron нужно один раз подключиться к NAS вручную, чтобы ключ хоста попал в `known_hosts`.

## Установка и запуск

```sh
install -m 700 bsd_backup.sh /usr/local/sbin/bsd_backup.sh
/usr/local/sbin/bsd_backup.sh; echo "rc=$?"
```

Запуск по расписанию — строка в `/etc/crontab` (каждый день в 03:00). `lockf` не даёт запустить второй экземпляр, пока не завершился первый:

```
0  3  *  *  *  root  /usr/bin/lockf -t 0 /var/run/bsd_backup.lock /usr/local/sbin/bsd_backup.sh
```

## Коды выхода

| Код | Значение |
|---|---|
| `0` | Успех: дамп и архив созданы и выгружены, старые копии удалены |
| `1` | Ошибка настройки: не создаётся `BACKUP_DIR`, не найдена утилита дампа, неизвестный `DB_TYPE` или ни один путь из `BACKUP_PATHS` не существует |
| `2` | Ошибка дампа базы |
| `3` | Ошибка создания архива |
| `4` | Ошибка выгрузки на NAS (локальные копии сохраняются) |

При ошибке недоделанный файл текущего шага удаляется, скрипт сразу завершается, а старые копии не трогаются. Поэтому серия неудачных запусков не уничтожит последние рабочие бэкапы.

## Логи

Сообщения пишутся в syslog с тегом `confluence-backup` и дублируются в stderr:

```sh
grep confluence-backup /var/log/messages
```

## Безопасность

- Файлы создаются с `umask 077` и сразу доступны только владельцу. В архиве лежат `/etc` (включая `master.passwd` и ключи хоста SSH) и конфиги с паролями, поэтому директорию `BACKUP_DIR` и директорию на NAS необходимо защищать так же, как сам сервер.
- В именах файлов нет двоеточий (`host-20261004-030000`), поэтому они допустимы и на NAS с SMB.
- Бэкап делается на работающем Confluence. Для полностью согласованной копии домашнего каталога можно останавливать сервис на время архивации или делать снапшот ZFS.

## Восстановление

```sh
# База (PostgreSQL)
gunzip -c host-ДАТА.db.gz | psql -U confluence confluence

# База (MySQL)
gunzip -c host-ДАТА.db.gz | mysql -u confluence confluence

# Файлы (распаковка во временную директорию для выборочного восстановления)
mkdir /tmp/restore && tar -xzf host-ДАТА.tar.gz -C /tmp/restore
```

Перед восстановлением базы Confluence необходимо остановить, а базу пересоздать пустой.
